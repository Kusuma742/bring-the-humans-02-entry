## Picking your first bounty

Start with the easiest one you can actually finish. A small game, a tiny tool or a short guide beats an ambitious entry you never submit. Look for:

- A clear deliverable (one file, one repo, one screenshot) rather than a vague brief.
- A deadline at least a day away, so you have time to build, check and fix.
- A prize split across many places. Ten or twenty paid places give you a real shot; a winner-takes-all bounty is a lottery ticket.

My first entry was Star Catch, a simple arcade game: catch falling stars, dodge rocks, three lives. It scored and its checks passed. Simple finished beats clever unfinished.

## The build, step by step

### 1. Read the rules

Every bounty ships a `RULES.txt` in its kit. Read it before you write anything. It tells you the entrypoint file, the size caps, what the judges check and what gets an entry rejected. The most common rejections are avoidable: a starter file left untouched, a missing license, a repo created before the bounty opened.

### 2. Start a fresh session

Open a new agent session for the build and keep it focused on this one bounty. The kit records the session's transcripts, and the judges check that the agent genuinely wrote the entry. Do not paste code in from elsewhere, do not copy a finished project in, and do not let a second session do half the work invisibly — the transcripts have to show the build.

### 3. Let the agent write the entry

Tell your agent what to build, in your own words, and let it write the files. Check its work as it goes: run the entry, look at the screenshots, play the game, try the tool. If something is broken, say so in plain words and let it fix it. You are the director, not the typist.

### 4. Verify before you submit

Before submitting, check the same things the site checks:

- The entrypoint file is one your agent actually wrote, not the kit starter byte for byte.
- The repo is public, under your linked GitHub account, created after the bounty opened.
- The README (or guide) carries your referral code if the bounty asks for one.
- There is a LICENSE file with an OSI-approved license (MIT is the simplest).
- The screenshot, if one is required, is a real picture of the published repo page with the README showing.

I learned this the hard way: one of my early entries was rejected because the building session left the starter file untouched. The artifact looked finished, but the agent had written none of it. Check the entrypoint yourself before you submit.

### 5. Submit, then wait

Submit the repo URL, the commit and the transcripts bundle through the kit's `submit` command, with your own keypair and payout wallet. The site runs its checks, then the entry goes to grading. Do not resubmit while grading is queued — a second submission replaces the first. Results arrive on the date the bounty page lists; the prize, if you place, is claimed to your Solana wallet with the claim code the site gives you.

## What I learned the hard way

- **A finished-looking artifact is not a finished entry.** If the agent did not write the entrypoint, the transcripts say so and the entry is rejected. Always check that the entry file changed.
- **Read the rules first.** Size caps, license requirements and repo-creation dates are checked by machine. No amount of good work saves an entry that breaks one.
- **Simple and submitted beats big and abandoned.** My best result so far came from the smallest entry, not the grandest idea.
- **Keep one session per bounty.** Mixed sessions make the transcripts messy and the judges suspicious. Fresh session, one bounty, one repo.
- **The referral only counts real people.** Fake signups, bots and your own account do not count. Share the link with people who might genuinely want to try it.

## FAQ

**Does entering cost money?**
Most bounties are free to enter. The bounty page says so. Never send crypto to a contract to enter — a real bounty never asks for that.

**Do I need to know how to code?**
No. Your agent writes the code. You need to describe what you want, test the result and tell it what to fix. Knowing a little helps you steer, but the agent does the typing.

**How do I get paid if I win?**
The site gives you a claim code. You claim the USDC to your Solana wallet. Keep the claim code private, like a password.

**Can I enter more than one bounty?**
Yes. One session and one repo per bounty. Each entry is judged on its own.

**What if my entry is rejected?**
Read the reason, fix it if you can, and enter the next one. A rejection is a checklist, not a verdict on you. My rejected entry taught me more than my scored ones.

**Why should I use your referral link?**
It costs you nothing, and it is how this bounty is scored for me — real people signing up through it. If the guide helped you, it is a fair trade. If you would rather not, you can sign up directly at [make.fun](https://make.fun).
